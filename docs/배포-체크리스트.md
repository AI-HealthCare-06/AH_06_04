## 1. EC2 준비 (처음 한 번)

- [ ] 인스턴스 크기: **t3.small(메모리 2GB) 이상**. 프리 티어(1GB)면 mysql + fastapi(워커 3) + 챗봇 + nginx 에서 메모리 부족으로 죽을 수 있다 → 최소 swap 2GB 추가
  ```bash
  sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
  echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  ```
- [ ] Docker + Compose 플러그인 설치 → `ubuntu` 사용자를 docker 그룹에 추가 (`sudo usermod -aG docker ubuntu` 후 다시 접속)
  (설치 방법은 Docker 공식 문서 "Install Docker Engine on Ubuntu" 를 따른다 — 버전마다 명령이 바뀐다)
- [ ] `mkdir -p ~/project/nginx` (스크립트도 만들지만 확인용)
- [ ] **보안그룹 인바운드는 22·80·443 만.** DB(3306)·redis(6379)·8000 은 열지 않는다 (운영 compose 도 호스트에 안 연다)

## 2. `envs/.prod.env` 만들기

`envs/example.prod.env` 를 복사해서 값을 채운다. `.gitignore` 라 레포에 안 올라간다.
**`ENV=prod` 이면 아래 값이 비었거나 예시 값일 때 서버가 켜지지 않는다** (일부러 막아 둠).

- [ ] `SECRET_KEY` — 새로 만들기: `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` (32자 이상)
  (챗봇은 compose 가 이 값을 `LOGIN_SECRET_KEY` 로 넘겨서 같은 토큰을 쓴다)
- [ ] `DB_PASSWORD` · `DB_ROOT_PASSWORD` — 새 값
- [ ] `COOKIE_DOMAIN` — 실제 도메인 (localhost 면 켜지지 않음)
- [ ] `OPENAI_API_KEY` = 팀 키
- [ ] **`DOCKER_USER` · `DOCKER_REPOSITORY` · `APP_VERSION` · `CHATBOT_VERSION` = 스크립트에 입력할 값과 똑같이.** EC2 는 이 값으로 이미지를 받는다 (다르면 스크립트가 멈춘다)
- [ ] AI 모드 결정 (아래 4번)

## 3. 실행

```bash
./scripts/deployment.sh
# 선택: 1 3   (fastapi + chatbot. ai_worker 는 아직 실제 작업이 없어 올리지 않는다)
```

스크립트가 하는 일 (첫 배포도 같은 순서):
1. EC2 에 `~/project/nginx` 를 만들고 `.env`·compose·nginx 설정 복사
2. `mysql`·`redis` 를 먼저 띄우고 healthy 까지 기다림
3. 새 fastapi 이미지로 **기동 전에** `aerich upgrade` (아직 안 한 마이그레이션만 — 빈 DB 면 0번부터). 운영 compose 의 fastapi 도 켜질 때마다 `aerich upgrade` 를 먼저 돌리고, 실패하면 뜨지 않는다
4. 고른 서비스 교체 → nginx 띄움

https 는 `scripts/certbot.sh` 로 인증서를 먼저 받는다.

## 4. AI 모드 — [결정 10/24] 데모데이까지 B안 (감수 전 데모 운영)

| 설정 | **지금 (B안 · 데모)** | 감수 끝난 뒤 (정식) |
|---|---|---|
| `GUIDE_LLM_MODE` / `OCR_MODE` / `CHAT_LLM_MODE` | `openai` | `openai` |
| `GUIDE_ALLOW_UNREVIEWED_DOCS` / `CHAT_ALLOW_UNREVIEWED_DOCS` | `true` | `false` |
| `CHAT_APP_ENV` | `demo` | `prod` |
| 결과 | 감수 전 안내문도 근거로 씀 · 화면 맨 위 '감수 전 데모' 띠 + 챗봇 답 아래 '감수 전 자료' 표시 | **감수(`reviewed: true`)된 안내문만** 근거 · 띠 사라짐 |

- `CHAT_APP_ENV=demo` 는 prod 와 같은 검사(가짜 LLM 금지 · 로그인 키 필수)를 하고, 감수 전 안내문만 허용한다. `dev` 를 운영에 쓰지 않는다.
- `GUIDE_ALLOW_UNREVIEWED_DOCS` 와 `CHAT_ALLOW_UNREVIEWED_DOCS` 는 **항상 같이** 바꾼다 (화면 맨 위 띠는 가이드 쪽 값만 보고 뜬다).
- 안내문이 바뀌면(#26 에서 5개 교체) 예전 안내문으로 만든 가이드가 재사용될 수 있다 → 배포는 **빈 DB 로 새로 시작**하고 시연 데이터는 `scripts/demo/seed_demo_day.py` 로 넣는다.
- 배포는 **#26 까지 머지한 뒤에** (그 전 코드는 '가짜 예시' 안내문이 근거로 나간다).
- 지금 안내문은 **모두 `reviewed: false`**. 멘토·의료진이 확인한 문서만 `true` 로 바꾼다 (더미로 바꾸지 않는다).
- 발표에서 "의료진 감수 전 데모 자료이며, 감수된 문서만 쓰는 정식 모드가 이미 구현돼 있다"고 설명한다.
- 화면에는 출처·면책 문구가 항상 붙는다.
- 검색 방식: 운영은 **낱말 검색**(`SEARCH_MODE` 기본값 keyword). 벡터·혼합 검색은 `chatbot/scripts/eval_search.py` 로 비교한 결과를 발표 근거로 쓴다 (켜려면 `SEARCH_MODE=hybrid`·`EMBEDDING_MODE=openai` + 임베딩 비용·P95 재확인).

## 알려진 한계 (발표 질문 대비)

- 챗봇은 토큰 서명만 확인하고 DB 의 계정 상태는 보지 않는다 → 탈퇴·차단 계정도 토큰이 살아 있는 최대 60분 동안 챗봇 사용 가능 (팀 API 는 차단 계정 거절)
- 회원 탈퇴(`DELETE /api/v1/users/me`)는 팀 DB 의 계정·진료기록·가이드·OCR·병원 요청·알림을 지운다. **챗봇 대화(챗봇 SQLite)는 같이 지우지 못하고** 보관 기간(30일) 뒤 자동 삭제된다
- [최종 점검 10/25] 로그인 토큰이 실제로는 약 10시간(시간대 계산 버그), refresh 는 약 55년이던 것을 고쳤다 → 이제 access 60분 · refresh 14일
- 진료기록을 지워도 그 기록으로 만든 가이드는 남는다 (`SET_NULL`) — 개인정보 설명에 맞춰 '같이 삭제' 로 바꿀지 팀 결정 필요
- P95 는 한 명이 순서대로 부른 측정이라 동시 사용자 부하는 반영되지 않는다
- 법·개인정보(국외 이전 고지·동의 문구)는 **전문가 확인 필요** — 가입 동의 · 약관 전문은 화면에 '데모 · 법무 검토 전 초안' 으로 표시
- [배포 전 v2] 동의 기능 전에 가입한 계정은 `privacy_agreed_at` · `terms_agreed_at` 이 비어 있고, 동의 여부를 확인하는 로직은 없다. 지금 배포 DB 의 기존 계정은 시연용 가짜 계정뿐이라 **이번에는 재동의 화면 없이 간다** (#41 리뷰). **정식 서비스 단계에서는 동의 시각이 비어 있는 계정에 재동의 화면을 만든다**
- [배포 전 v2] #38 · #39 는 닫힘 — 내용은 main · #41 에 들어가지 않았다. 다시 올리면 마이그레이션 번호를 `12_` 부터 쓴다 (`11_` 은 #41 의 `11_…_agreements`)
- [배포 전 v2] 로그아웃은 브라우저의 refresh 쿠키를 지운다. 이미 빼낸 refresh 토큰을 서버에서 무효로 하는 목록은 없다 (최대 14일)
