# 데모데이 시연 대본 (약 3분 30초)

> 발표 슬라이드 '라이브 데모' 장과 같은 순서. 모든 데이터는 **가짜**(가짜 환자·가짜 병원)이고 실제 환자 정보는 넣지 않는다.

## 전날 준비

1. 배포 서버 `.env` 가 데모 운영 모드(B안)인지 확인 — `CHAT_APP_ENV=demo`, `*_ALLOW_UNREVIEWED_DOCS=true`, AI 모드 `openai` (`docs/배포-체크리스트.md` 4장)
2. 시연 데이터 넣기 (가짜 데이터만):
   ```bash
   DEMO_PASSWORD='시연용비밀번호' BASE_URL=https://배포주소 uv run python scripts/demo/seed_demo_day.py --yes
   ```
   → 주인공 계정 `demo.cn01@example.com` (중국어 화면 · 위챗), 진료기록·AI 가이드·복약 알림·병원 연락 요청, 병원 접수대 계정 `demo.staff@example.com` 이 준비된다
3. 병원 접수대 계정에 관리자 권한 (한 번만, 배포 서버에선 `docker compose exec fastapi uv run --no-sync python -m app.commands.make_admin demo.staff@example.com`)
   → 두 번째 브라우저 창에서 `demo.staff` 로 로그인하면 홈에 **병원 접수대** 버튼이 보인다 (`#/desk`)
4. **백업 영상**: 아래 순서를 화면 녹화해 둔다 (네트워크·AI 서버 문제 대비)
5. 브라우저는 시크릿 창 + 휴대폰 크기(개발자 도구 375px)로, 언어 中文

## 막혔을 때

- AI 응답이 느리거나 실패 → "하루 한도·실패 처리도 설계돼 있다" 고 짚고 백업 영상으로 전환
- 로그인이 풀림 → 시드 스크립트로 만든 계정으로 다시 로그인 (데이터는 그대로)
- 응급 문장이 응급으로 안 잡힘 → 문장을 `打完玻尿酸以后喘不上气` 로 바꿔 시연 (규칙 기반 + 시험셋 결과는 발표 자료 참고)
