# 배포 준비 — EC2·Docker Hub 를 직접 마련할 때 (처음부터)

> `docs/배포-체크리스트.md` 는 "EC2 와 Docker Hub 가 이미 있다"고 가정한다. 이 문서는 그 **앞 단계**다.
> 부트캠프에서 EC2 를 제공하면 1장은 건너뛰고 받은 IP·키 파일만 쓰면 된다. 제공 여부는 매니저에게 먼저 확인.
> AWS·Docker Hub 화면의 버튼 이름·위치는 자주 바뀐다. 아래는 "무엇을 고르고 왜 그런지"까지만 적고, 정확한 화면은 그 옆에 적은 공식 문서를 따른다.

## 0. 전체 그림 (10분이면 읽는다)

```
내 PC ──(1) docker build·push──▶ Docker Hub(이미지 창고)
  │                                      │
  └──(2) ssh + scripts/deployment.sh ───▶ EC2(리눅스 서버) ──(3) docker pull──▶ 컨테이너 실행
                                           └ nginx :80/:443 → fastapi :8000 · chatbot :8002 · mysql · redis
```

- **EC2** = 24시간 켜 둘 리눅스 컴퓨터 한 대. 우리 서비스가 여기서 돈다.
- **Docker Hub** = 빌드한 이미지(프로그램 묶음)를 올려 두는 창고. EC2 가 여기서 받아 간다.
- **도메인** = 있으면 https(자물쇠) 가능, 없으면 `http://IP` 로 데모. 데모데이엔 IP 로도 충분하지만 챗봇 음성 읽기(Web Speech)·클립보드 등 일부 브라우저 기능은 **https 에서만** 되는 것이 있어, 도메인이 있으면 좋다.

## 1. EC2 한 대 만들기 (처음 한 번, 약 30분)

공식 문서: AWS "Amazon EC2 시작하기 — Linux 인스턴스 시작" (콘솔에서 `EC2` → `인스턴스 시작`)

고를 것과 이유:

| 항목 | 고를 값 | 왜 |
|---|---|---|
| 리전 | 서울(ap-northeast-2) | 심사위원·우리 모두 한국에서 접속 → 지연 최소 |
| AMI(운영체제) | Ubuntu Server 24.04 LTS (또는 22.04) | `scripts/deployment.sh` 가 `ubuntu` 사용자·apt 기준으로 쓰여 있다 |
| 인스턴스 유형 | **t3.small** (2 vCPU · 2GB) | mysql + fastapi(워커 3) + chatbot + nginx 를 1GB(t2.micro 프리 티어)에서 돌리면 메모리 부족으로 죽는다. 요금은 시간당 과금 — 데모데이까지 2주 켜 두면 수천 원~1만 원대 수준(리전·환율로 달라지므로 콘솔 요금 표시 확인 필요). 프리 티어로 버티려면 체크리스트 1장의 swap 2GB 추가 |
| 키 페어 | **새로 만들기** → `.pem` 다운로드 | 이 파일이 서버 열쇠. `~/.ssh/glowpass.pem` 으로 옮기고 `chmod 400`. **잃어버리면 서버에 못 들어간다**, 레포·채팅에 절대 올리지 않는다 |
| 네트워크/보안그룹 | 인바운드 **22(SSH)·80(HTTP)·443(HTTPS)** 만 | 3306(DB)·6379(redis)·8000 은 열지 않는다. 22 는 가능하면 "내 IP" 로 제한 |
| 스토리지 | 20GB gp3 | 기본 8GB 는 도커 이미지 몇 번 받으면 찬다 |

만든 뒤:

1. **탄력적 IP(Elastic IP) 할당 → 인스턴스에 연결.** 안 하면 서버를 껐다 켤 때마다 IP 가 바뀌어 `.env`·슬라이드·백업 영상 주소가 전부 틀어진다.
2. 접속 확인 (내 PC 터미널):
   ```bash
   chmod 400 ~/.ssh/glowpass.pem
   ssh -i ~/.ssh/glowpass.pem ubuntu@<탄력적IP>
   ```
3. 서버 안에서 Docker 설치 — Docker 공식 문서 "Install Docker Engine on Ubuntu" 의 apt 방식 그대로. 끝나면:
   ```bash
   sudo usermod -aG docker ubuntu   # 접속을 끊고 다시 들어와야 적용
   docker compose version           # 'Docker Compose version v2...' 가 나오면 됨
   ```
4. (프리 티어로 버틸 때만) 체크리스트 1장의 swap 2GB 명령.

## 2. Docker Hub 계정·토큰 (약 10분)

공식 문서: Docker Docs "Create and manage access tokens"

1. hub.docker.com 가입 (무료). **사용자 이름**이 곧 `DOCKER_USER`.
2. 저장소(Repository) 하나 만들기 — 이름 예: `glowpass`, **Public**. (Private 는 무료 1개까지라 Public 이 편하다. 이미지 안에 `.env` 는 들어가지 않으니 괜찮다 — 단 Dockerfile 이 `.env` 를 COPY 하지 않는지 아래 3장에서 확인)
   → 이 이름이 `DOCKER_REPOSITORY`. 이미지 태그는 스크립트가 `app-<버전>`, `chatbot-<버전>` 으로 붙인다.
3. Account settings → Security(또는 Personal access tokens) 에서 토큰 발급, 권한 **Read & Write**. 토큰은 한 번만 보여 준다 → 바로 내 PC 에서 로그인:
   ```bash
   docker login -u <DOCKER_USER>     # 비밀번호 자리에 토큰 붙여넣기
   ```
   `scripts/deployment.sh` 도 실행 중에 같은 값을 물어본다.

## 3. 올리기 전 내 PC 에서 할 것 (약 20분)

```bash
# 1) 비밀값 새로 만들기 — 결과를 envs/.prod.env 에만 붙여 넣는다
python3 -c "import secrets; print('SECRET_KEY=' + secrets.token_urlsafe(48))"
python3 -c "import secrets; print('DB_PASSWORD=' + secrets.token_urlsafe(24))"
python3 -c "import secrets; print('DB_ROOT_PASSWORD=' + secrets.token_urlsafe(24))"

# 2) envs/.prod.env 만들기
cp envs/example.prod.env envs/.prod.env
#    채울 것: 위 3개 · OPENAI_API_KEY · COOKIE_DOMAIN(도메인 없으면 탄력적IP)
#    DOCKER_USER · DOCKER_REPOSITORY · APP_VERSION · CHATBOT_VERSION (예: 1.0.0)
#    AI 모드는 체크리스트 4장(B안): CHAT_APP_ENV=demo, *_ALLOW_UNREVIEWED_DOCS=true, *_MODE=openai

# 3) 레포에 비밀값이 섞이지 않았는지 (공개 레포!)
git status --short | grep -i env      # envs/.prod.env 가 보이면 안 된다 (.gitignore 확인)
grep -rn "sk-" --include="*.py" --include="*.js" --include="*.yml" . | grep -v ".venv" | head
grep -n "COPY .*\.env" app/Dockerfile chatbot/Dockerfile          # 아무것도 안 나와야 한다

# 4) 도커 빌드가 되는지 (푸시 전에 한 번 — 처음엔 10분 넘게 걸릴 수 있다)
docker build --platform linux/amd64 -t glowpass-app-test -f app/Dockerfile .
docker build --platform linux/amd64 -t glowpass-chat-test -f chatbot/Dockerfile chatbot
```

> M1/M2 맥이면 `--platform linux/amd64` 가 꼭 필요하다 (EC2 는 amd64). 스크립트는 이미 붙여 놓았다.

## 4. 배포 (체크리스트 3장과 같다)

```bash
./scripts/deployment.sh      # 1 3 선택 (fastapi + chatbot), 키 파일명·IP 입력
```

끝나면 체크리스트 5장 "배포 직후 확인 (10분)" 으로.

## 5. 배포 후 바로 할 일

```bash
# 내 PC 에서 — 시연 데이터(가짜)는 HTTP 로 넣으므로 서버에 들어갈 필요 없다 (도커 이미지엔 scripts/ 가 없다)
DEMO_PASSWORD='시연용비밀번호' BASE_URL=http://<IP> uv run python scripts/demo/seed_demo_day.py --yes

# EC2 에서 — 접수대 계정 권한 (app/ 안의 명령이라 컨테이너에서 된다)
ssh -i ~/.ssh/glowpass.pem ubuntu@<IP>
cd ~/project && docker compose exec fastapi uv run --no-sync python -m app.commands.make_admin demo.staff@example.com
```

- P95 재측정: 내 PC 에서 `BASE_URL=http://<IP> DEMO_PASSWORD='...' uv run python scripts/perf/measure_p95.py --n 50` → 슬라이드 'API' 장의 빈칸에 숫자 넣기
- 백업 영상을 실제 주소로 다시 녹화
- 슬라이드 '라이브 데모' 장·발표 대본의 주소 바꾸기

## 6. 비용·정리

- 데모데이(11/5) 다음 날 **인스턴스 종료 + 탄력적 IP 해제**(연결 안 된 탄력적 IP 는 과금된다) + 스냅샷/볼륨 삭제.
- 포트폴리오로 남기려면 종료 대신 "중지"하고 필요할 때만 켠다 (중지 중에도 볼륨·탄력적 IP 요금은 조금 나온다).

## 막히면

| 증상 | 먼저 볼 것 |
|---|---|
| `ssh: Permission denied (publickey)` | 키 파일 경로·`chmod 400`·사용자 이름 `ubuntu` |
| `ssh: connection timed out` | 보안그룹 22 가 내 IP 에 열렸는지, 탄력적 IP 가 연결됐는지 |
| 스크립트가 `docker push` 에서 denied | `docker login` 다시, 저장소 이름이 `DOCKER_USER/DOCKER_REPOSITORY` 와 같은지 |
| EC2 에서 컨테이너가 자꾸 죽음 | `docker compose logs --tail 50 fastapi` → `MemoryError`/`Killed` 면 메모리 부족(t3.small 또는 swap) |
| `ENV=prod` 인데 서버가 안 켜짐 | 일부러 막은 것 — `.prod.env` 에 예시값(`localhost`, "…넣으세요" 문구)이 남아 있다. `docker compose logs fastapi` 에 어떤 값이 문제인지 찍힌다 (체크리스트 2장) |
